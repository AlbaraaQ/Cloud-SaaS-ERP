# تشغيل النظام محلياً — Run the stack locally

> كل الأوامر تُنفَّذ من جذر المستودع. تحتاج Node ‎22+‎ و pnpm ‎9.15‎ (`corepack enable`).

## 1. التثبيت وتجهيز متغيرات البيئة

```bash
pnpm install
pnpm env:setup     # ينشئ .env في الجذر ويولّد مفاتيح JWT وأسراراً عشوائية
pnpm env:check     # يتحقق أن كل متغير مطلوب موجود ويطبع مصدر كل ملف .env
```

`pnpm env:setup` يكتب ملف `.env` واحداً في جذر المستودع (صلاحيات 600، مستثنى من Git).
كل التطبيقات تقرأ منه: الـ API عبر `@erp/config`، وتطبيقا Next عبر `scripts/dotenv.mjs`
داخل `next.config.mjs`. لا حاجة لنسخ ملفات `.env` داخل كل تطبيق.

## 2. قاعدة البيانات

### أ. مع Docker

```bash
pnpm db:up         # postgres 16 + redis
```

### ب. بدون Docker (موصى به على أجهزة بلا Docker)

```bash
pnpm db:local      # يشغّل PostgreSQL 16 مدمجاً على نفس منفذ DATABASE_URL — اتركه يعمل
```

`pnpm db:local` يستخدم `embedded-postgres` (نفس المحرك الذي تستعمله الاختبارات)، وينشئ
دورَي `erp_api` و`erp_migrator` وقاعدة البيانات تلقائياً. بيانات القاعدة في مجلد مؤقت؛
لجعلها دائمة: `DB_LOCAL_DATA_DIR=/path DB_LOCAL_PERSIST=true pnpm db:local`.

## 3. الترحيلات والبيانات الأولية

```bash
pnpm db:migrate    # يطبّق ملفات SQL بالترتيب مع تحقق من البصمة
pnpm db:seed       # البيانات الأولية — لا يحتاج أي متغيّر إضافي بعد pnpm env:setup
```

`pnpm env:setup` يولّد أربع كلمات مرور قوية داخل `.env` ويطبعها مرة واحدة على الشاشة،
و`pnpm db:seed` يقرأها من هناك. الأمر **قابل للتكرار بأمان** (idempotent): تشغيله مرتين
لا يغيّر شيئاً.

### ماذا يُنشئ البذر؟

**الطبقة الأولى — المنصة** (`seedPlatform`):

* سجل الصلاحيات (114 صلاحية) وإعدادات المنشأة الافتراضية.
* الأدوار الأساسية الثلاثة: `Owner` / `Accountant` / `Cashier`.
* **مدير المنصة (Super admin)** داخل منشأة داخلية رمزها `platform` — الحساب الوحيد الذي
  يرى `/platform`.
* المنشأة التجريبية `demo` ومالكها.

**الطبقة الثانية — بيانات العمل** (`seedDemoData`، تُعطَّل بـ `SEED_DEMO_DATA=false`):

| العنصر | التفصيل |
| --- | --- |
| الباقات | `starter-monthly` 199، `pro-monthly` 499، `pro-yearly` 4990 (SAR) |
| الاشتراك | اشتراك **فعّال** لمنشأة `demo` على `DEMO_PLAN_CODE` لمدة `DEMO_SUBSCRIPTION_MONTHS` |
| المنشأة | العملة الأساسية، بطاقة المنشأة، الفرع `MAIN`، المستودع `MAIN`، قائمة أسعار افتراضية |
| الخزائن | صندوق رئيسي + حساب بنكي، كلاهما مربوط بحسابه في دليل الحسابات (`1101` / `1102`) |
| دليل الحسابات | 49 حساباً عربياً على خمس مجموعات (أصول، خصوم، حقوق ملكية، إيرادات، مصروفات) |
| مراكز التكلفة | `ADMIN` / `SALES` / `STORE` |
| التقويم المالي | السنة المالية الحالية + 12 فترة شهرية مفتوحة |
| قيد افتتاحي | `JE-000001` مُرحَّل: صندوق 50,000 + بنك 180,000 + أثاث 20,000 = رأس مال 250,000 |
| المستخدمون | محاسب + أمين صندوق بجانب المالك، كلٌ على دوره |

بعد البذر تفتح شاشة **ميزان المراجعة** فتجد أرقاماً حقيقية، و**سند القيد** التالي يأخذ
الرقم `JE-000002` تلقائياً لأن عدّاد المستندات يُقدَّم مع القيد الافتتاحي.

### المتغيّرات (كلها اختيارية، وكلها موثّقة في `.env.example`)

| المتغيّر | الافتراضي | الأثر |
| --- | --- | --- |
| `PLATFORM_ADMIN_EMAIL` / `_NAME` / `_PASSWORD` | `admin@platform.test` | مدير المنصة |
| `PLATFORM_TENANT_CODE` | `platform` | رمز المنشأة الداخلية التي يدخل بها |
| `DEMO_TENANT_CODE` / `_NAME` | `demo` | المنشأة التجريبية |
| `DEMO_OWNER_EMAIL` / `_NAME` / `_PASSWORD` | `owner@demo.test` | المالك |
| `DEMO_ACCOUNTANT_*` / `DEMO_CASHIER_*` | `accountant@demo.test` / `cashier@demo.test` | مستخدمان إضافيان |
| `SEED_DEMO_DATA` | `true` | `false` = منشأة فارغة (سجل صلاحيات + أدوار + مالك فقط) |
| `DEMO_PLAN_CODE` / `DEMO_SUBSCRIPTION_MONTHS` | `pro-monthly` / `12` | الاشتراك المُفعَّل |
| `DEMO_FISCAL_YEAR` | السنة الحالية | سنة التقويم المالي |
| `DEMO_OPENING_ENTRY` | `true` | `false` = بلا قيد افتتاحي |

> **كلمات المرور لا تُخترع ضمناً.** أي حساب متغيّر كلمة مروره فارغ يُنشأ بحالة `invited`
> مع `must_change_password`، أي لا يمكن الدخول به حتى يضبط له مسؤول كلمة مرور. سياسة
> كلمة المرور: 12 محرفاً على الأقل، ثلاث فئات محارف، وألّا تحتوي اسم المستخدم أو الجزء
> الذي يسبق `@` في البريد.

## 4. التشغيل

```bash
pnpm dev           # api :3000 — admin :3001 — customer :3002
```

| الواجهة | العنوان | الدخول |
| --- | --- | --- |
| لوحة التحكم (الموظفون + المنصة) | http://localhost:3001 | رمز المنشأة + البريد + كلمة المرور |
| بوابة العملاء | http://localhost:3002 | نفس البيانات |
| وثائق الـ API | http://localhost:3000/api/docs | — |
| فحص الصحة | http://localhost:3000/health/ready | — |

### تسجيل الدخول

* **مدير المنصة:** رمز المنشأة `platform` + `admin@platform.test` + `PLATFORM_ADMIN_PASSWORD`
  → تظهر له وحدة **لوحة تحكم المنصة** 🛡️ في القائمة الجانبية.
* **مالك منشأة:** رمز المنشأة `demo` + `owner@demo.test` + `DEMO_OWNER_PASSWORD`.
* **محاسب:** `accountant@demo.test` + `DEMO_ACCOUNTANT_PASSWORD` (بلا صلاحيات إدارة المنشأة).
* **أمين صندوق:** `cashier@demo.test` + `DEMO_CASHIER_PASSWORD`.
* كل كلمات المرور مكتوبة في `.env` بعد `pnpm env:setup`؛ لعرضها:
  `grep PASSWORD .env`.
* **عميل جديد:** زر «ليس لديك حساب؟ اشترك الآن» في شاشة الدخول ينشئ منشأة جديدة
  (`POST /api/v1/signup`) مع طلب تفعيل معلّق يعتمده مدير المنصة.

## 5. أول جلسة عمل محاسبية

بعد `pnpm db:seed` تكون منشأة `demo` جاهزة للعمل فوراً — الفرع والسنة المالية ودليل
الحسابات والقيد الافتتاحي كلها موجودة. الجولة المقترحة:

1. `المحاسبة ← ميزان المراجعة` — يظهر 250,000 مدين مقابل 250,000 دائن من القيد الافتتاحي.
2. `المحاسبة ← شجرة الحسابات` — تصفّح المجموعات الخمس.
3. `المحاسبة ← سند قيد` — سجّل قيداً متوازناً جديداً؛ الفرع والفترة يُشتقّان من التاريخ
   تلقائياً، والرقم يتسلسل من `JE-000002`.
4. `المحاسبة ← كشف حساب` — راجع حركة «الصندوق الرئيسي».

ولبدء منشأة **فارغة** بدل التجريبية: `SEED_DEMO_DATA=false pnpm db:seed`، ثم:

1. `الإعدادات ← بطاقة فرع` — أنشئ الفرع الرئيسي.
2. `المحاسبة ← الفترات المحاسبية` — أنشئ السنة المالية؛ تُولَّد 12 فترة شهرية تلقائياً.
3. `المحاسبة ← دليل الحسابات` — ابنِ شجرة حساباتك.

## 6. جولة الوحدات التشغيلية

كل الشاشات أدناه تعمل على نقاط النهاية الحقيقية — لا توجد بيانات وهمية في الواجهة. الترتيب
مقصود: كل خطوة تُنتج البيانات التي تحتاجها الخطوة التالية.

1. **الإعدادات ← الربط المحاسبي** — قبل أي ترحيل. حدّد حسابات المبيعات والمشتريات وضريبة
   المخرجات/المدخلات والمخزون وتكلفة المبيعات والذمم المدينة/الدائنة والصندوق والبنك.
   بدون هذا الجدول يردّ الـ API بـ `ACCOUNT_PROFILE_MISSING` ولا يخمّن حساباً.
2. **المستودعات ← بطاقة مجموعة / وحدة / دليل المواد** — المجموعة والوحدة شرطان لإنشاء أي
   صنف.
3. **المشتريات ← بطاقة مورد** ثم **فاتورة المشتريات** — أنشئها مسودة، أضف مصاريف الشراء
   (تُوزَّع على الأسطر بالقيمة أو بالكمية)، ثم رحّلها: يدخل المخزون بالتكلفة النهائية ويُقيَّد
   الشراء وضريبة المدخلات والذمة الدائنة.
4. **المبيعات ← بطاقة عميل** ثم **فاتورة مبيعات** أو **نقطة البيع** — الترحيل يُخرج المخزون،
   يُقيّد الإيراد وضريبة المخرجات، ثم يُقيّد تكلفة البضاعة المباعة من القيمة التي قوّم بها
   المخزون الحركة فعلياً.
5. **الخزينة ← سند قبض / سند صرف** — سند بحالة مسودة ثم ترحيل بقيد من طرفين، مع الإلغاء.
6. **المستودعات ← تسوية مخزنية / مناقلة / الأرصدة والحركات** — الجرد يولّد قيد الفروقات.
7. **الموظفون والرواتب** — الإدارات ← الوظائف ← الموظفون (مكوّنات الراتب) ← الحوافز والجزاءات
   ← *إستحقاق راتب*: معاينة الشهر، إنشاء المسيّر، ترحيله بقيد المصروف/الاستحقاق، ثم صرفه من
   موقع نقدي.
8. **إدارة المراسي** — المجموعة وتسعيرها ← المركب ومُلّاكه ← الحجز وإضافاته ← *إصدار فاتورة
   التأجير* (تُحسب من التسعير والمدة) ← المخالفات.
9. **إدارة المشاريع** — المشروع (قيمة العقد ونسبة المحتجز) ← المراحل ← بنود الكميات ←
   *مستخلص*: نسبة تنفيذ لكل بند، ثم ترحيله (إيراد + ذمة مدينة + محتجز) ثم الإفراج عن المحتجز.

## 8. ملاحظات تشغيلية

* **الـ API في وضع التطوير يُترجم بـ `tsc` وليس `tsx`.** esbuild (المستخدم داخل tsx) لا
  يولّد `emitDecoratorMetadata`، وبدونها يفشل حقن التبعيات في NestJS عند الإقلاع
  (`Nest can't resolve dependencies of the TenantGuard`). المشغّل الجديد
  `apps/api/scripts/dev.mjs` يجمع بين `tsc --watch` و`node --watch`.
* **لا تضبط `NEXT_PUBLIC_API_BASE_URL`** إلا إذا كان الـ API على أصل مختلف؛ القيمة
  الافتراضية (فارغة) تعني نفس الأصل عبر وسيط Next، وهو ما يجعل الواجهة تعمل من أي جهاز
  في الشبكة بلا إعداد CORS.
* `SIGNUP_ENABLED=false` يعطّل نافذة الاشتراك الذاتي في النشرات الخاصة.
