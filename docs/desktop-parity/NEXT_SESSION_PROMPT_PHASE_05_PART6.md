## 3) نطاق الجزء السادس — بالترتيب

1. **الأرقام التسلسلية والدفعات (Serial & Lot lifecycle)** — ربط الرقم التسلسلي/الدفعة بسطر المستند كما يفعل `InvoiceItemDetail`، مع انتقال الرقم بين «متاح» و«مباع» واستعلام برقم الصنف. الجداول المرجعية: `stock_lots` و`stock_serials` الموجودة أصلاً؛ أي إضافة عمود تكون بترحيل جمعي جديد (0038) مع ملف `down/` مقابل.
2. **طلب المستودع** — كما في الديسكتوب: **نوع مستند** داخل سندات المخزون (`📦 طلب مستودع`) لا كيان جديد منفصل، مع طباعة `RptInvOrderItems.repx` كمرجع أعمدة، واعتماد/صرف الطلب لاحقاً.
3. **التسليم** — شاشة `/inventory/deliveries` الحالية تُبنى على غرار `frmInvItemsDeliveries`: المسلَّم سابقاً مقابل كمية التسليم، `تسليم الكل`، `اعتماد التسليم`، وتاريخ الاستلام.
4. **شاشة أمر الإنتاج** — `/inventory/production` مكتملة وظيفياً بالجزء الخامس ( المكوّنات من البطاقة، التحويل بين الوحدات، منع الدوران)؛ المطلوب هنا استكمال ترويستها إلى مرجع `frmProductionOrder`: `رقم المرجع`، `تاريخ المرجع`، `الوحدة`، `📊 الكمية المتوفرة`، وطباعة `rptProductionOrder.repx`.
5. **تقارير المخزون والدوران** — `/inventory/reports` (أو ما يقابلها) بفلاتر `كل الفروع / كل المستودعات / كل الفترة` وأفعال `عرض · طباعة · Excel`، ومحتواها من `rptInventoryReport.repx` و`rptItemsExpire.repx` و`rptItemsTotalGrd.repx`. دوران المخزون (turnover) يُحسب من حركة الأرصدة لا من جدول ملخّص.

## 4) قواعد ملزمة (مجرَّبة في الأجزاء السابقة)

- **البيانات قبل الواجهة**: الترحيل أولاً، ثم الخدمة والاختبارات، ثم الشاشة. لا شاشة بلا نهاية خلفية حقيقية، ولا بيانات وهمية.
- **كل ترحيل جمعي** (إضافة أعمدة/فهارس nullable فقط) ومع ملف `migrations/down/00XX_*.down.sql` يقابله. لا حذف بيانات.
- **بعد أي تعديل على مخطط Drizzle**: `pnpm --filter @erp/database run build` ثم `npx tsc --noEmit -p apps/api/tsconfig.json` — وإلا ترى خطأ TS2769 لأن الـ API يتحقق من ملفات `.d.ts` المُولَّدة.
- **لا تبدأ المرحلة 06 قبل إغلاق نطاق المرحلة 05.** لا خدمة مصغّرة لكل واجهة، ولا فصل API: خلفية واحدة وقاعدة واحدة، مع فصل صارم للواجهات ونطاقات مستقلة.
- لا `*` في صلاحيات المنصة، ولا دور إدارة عام؛ `tenant_owner` يدير مؤسسته فقط. لا حذف وظيفة قائمة دون تفسير وبديل. حافظ على توافق الـ API.
- **التسميات من `Desktop_ERP` بنصها العربي**، ونسبة تطابق ≥ 90%؛ أي تسمية مخترَعة تُبرَّر في الملخّص النهائي.
- **لا تشغّل `next build` أثناء عمل `next dev` على نفس التطبيق** — كلاهما يستخدم `.next` وسيُفسد معاينة المستخدم (خطأ `__webpack_modules__[moduleId] is not a function`). أوقف `dev` أولاً، أو استخدم مجلد بناء آخر.
