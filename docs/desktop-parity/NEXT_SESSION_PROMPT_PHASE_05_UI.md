### ج) الفئات والقاعدة `Class/` — السلوك الذي يجب أن تعكسه كل شاشة

- `Class/InvoiceOper.cs` (س 5031): `ItemPrimaryQnty = ItemQuantity * UnitEquality`، وحركة المخزون (س 4275-4295) — مرجع عمود «الكمية بالوحدة الأساسية» في **كل** مستند.

### د) قاعدة ملزمة
**كل تسمية عمود أو تبويب أو زر في شاشات المخزون تُؤخذ من هذه الملفات بنصها العربي.** لا تخترع تسمية جديدة إلا لما لا مقابل له في الديسكتوب، واذكر ما اخترعته في الملخّص الختامي مع سببه.

## 3) المطلوب بالتحديد (لا تكتفِ بإعادة ترتيب العناصر)
الهدف البصري: نظام ERP حديث بمستوى Odoo/ERPNext — تخطيط واضح، تسلسل هرمي، مؤشرات، حالات، أفعال ظاهرة، بالعربية و RTL.

أ) طبقة مكوّنات جديدة في `apps/staff/components/` تُبنى عليها الشاشات بلا تكرار JSX:
1. `PageHeader` (عنوان + وصف + مسار + أزرار يميناً). 2. `FilterBar` شريط فلاتر **لاصق** (صنف/مستودع/فرع/فترة/حالة) مع «تطبيق/تفريغ» وحالة تحميل. 3. `StatTiles` بطاقات مؤشرات: **القيمة + الكمية + وصف** مع لون للحالات الحرجة. 4. `DataTable` مُطوَّر: رأس لاصق، صفوف مخططة، ترتيب أعمدة، صفوف قابلة للتوسّع، تذييل بالمجاميع، حالة فراغ مفسِّرة، حالة تحميل، تحديد عدد الصفوف. 5. `StatusTrack` شريط حالة كخطوات مرئية (مسودة → مُرسَلة → مُستلمة/مُرحَّلة → مُغلقة/مُلغاة). 6. `EmptyState` و`LoadingState` و`ErrorState` موحّدة بدل `—`. 7. `ActionBar` أفعال المستند (حفظ/ترحيل/فسخ/إغلاق/طباعة) مع تأكيد قبل الإجراءات المدمّرة. 8. `Tabs` لتبويبات بطاقة الصنف (عام/وحدات/بضاعة أول المدة/المكونات).

ب) إعادة بناء الشاشات بها، بالترتيب:
1. **`/inventory/vouchers`** (الأهم): تخطيط مقسوم — يمين قائمة السندات بحالة ولون وبحث، يسار السند المحدد (بياناته + شبكة أسطر + مجاميع + أفعال)؛ تبويبات: بضاعة أول المدة / إدخال / إخراج؛ صندوق مسح باركود يضيف سطراً؛ عمود وحدة + «الكمية بالوحدة الأساسية» (مرجع `InvoiceOper` س 5031).
2. **`/inventory/transfers`**: `StatusTrack` + شريط تقدّم لكل سطر (المُرسَل مقابل المُستلَم) + أفعال إرسال/استلام/إغلاق/إلغاء.
3. **`/inventory/adjustments`**: نموذج جرد — الرصيد الدفتري مقابل المجرود مقابل الفرق **بألوان**، شريط اعتماد التسوية، مجاميع العجز/الزيادة.
4. **`/inventory/item-card`**: صف بطاقات (افتتاحي/وارد/صادر/ختامي) للكمية **والقيمة** + **إجمالي الكميات وإجمالي المجموع** (كما في `rptItemDetails`)، فلاتر لاصقة، جدول برصيد متحرك قابل للتوسّع، تنسيق طباعة.
5. **`/inventory/in-transit`**: بطاقات (عدد الأصناف المعلّقة، قيمتها، المتأخرة) + تجميع حسب العمر (٠–٢ / ٣–٧ / أكثر من ٧ أيام) + إقفال (عودة/عجز) بسبب إلزامي.
6. **`/inventory/items`**: تحويلها إلى **تبويبات**: عام / وحدات / بضاعة أول المدة / المكونات (كما في `frmItems.xaml`)، مع دمج شاشة `item-units` داخل تبويب «وحدات» و`frmMultiBarcode` داخل «عام/باركود»، وإضافة تبويب «المكونات» (الجدول من `ItemComponent.cs`).
7. **`/inventory/item-units`**: بطاقات وحدات توضّح «1 علبة = 12 حبة» + قسم باركودات قابل للحذف.
8. **`/inventory/expiry`**: دلاء (منتهية / خلال أسبوع / شهر / ثلاثة أشهر) مع **سعر التكلفة والإجمالي** (كما في `rptItemsExpire`).
9. **`/inventory/below-minimum`**: بطاقات (عدد الأصناف، قيمة العجز) + أعمدة: المجموعة، الصنف، سعر الشراء، سعر البيع، الرصيد، **حد الطلب** + زر «تغطية».
10. **`/inventory/production`**: ترويسة (الرقم، التاريخ، المرجع، المنتج، الوحدة، البيان) + جدول مكوّنات بأعمدة الديسكتوب (رمز الصنف، الصنف، الوحدة، الكمية الأساسية، الكمية، السعر، المجموع).
11. ثم البقية بنفس النظام: `levels`, `movements`, `requests`, `deliveries`, `lots`, `serials`, `barcodes`, `units`, `categories`, `warehouses`.
12. **جديد `/inventory/overview`**: لوحة المخزون (قيمة المخزون، تحت حد الطلب، قاربت الانتهاء، بضاعة في الطريق، مسودات تنتظر الترحيل) بروابط لكل شاشة + إضافتها إلى `lib/navigation.ts`.

ج) تحسينات تجربة: رسائل نجاح/خطأ عربية واضحة، تأكيد قبل الإجراءات المدمّرة، أرقام وتواريخ بصيغة عربية موحّدة، skeleton في كل قائمة، حالة فراغ تشرح وتقترح فعلاً، تخطيط متجاوب و RTL سليم، `@media print` مطابق لتقارير `.repx`، اختصارات (`F2` سطر جديد، `Enter` ترحيل، `Esc` إغلاق).

## 4) حدود صارمة
- **لا تغيير لأي عقد أو نقطة نهاية API**؛ التغيير في طبقة العرض فقط، والحقل الناقص يُضاف من الخلف **بالإضافة فقط** + ترحيل آمن.
- لا إطار CSS خارجي ولا مكتبة واجهات؛ وسّع `globals.css` ومكوّنات المشروع.
- الحفاظ على عزل المستأجرين و RBAC، ولا منح صلاحية `*`.
- لا شاشات وهمية بلا API حقيقي، ولا حذف وظيفة قائمة (عند دمج `item-units` داخل تبويب، أبقِ المسار السابق يعيد التوجيه).
- العمل والبوش على الفرع `arena/01a0889e-cloud-saas-erp` فقط.

## 5) تعريف «تم» (قابل للقياس — تحقّق منه بنفسك)
- لا `<table>` يدوية في شاشات المخزون (استبدالها بـ `DataTable`).
- ≥ 12 شاشة تستخدم `PageHeader` و`FilterBar`؛ كل شاشة قائمة تستخدم `LoadingState` و`EmptyState`.
- كل شاشة من الشاشات الاثنتي عشرة أعلاه فيها **عنصر تصميمي جديد فعلي واحد على الأقل**: صف مؤشرات، أو شريط حالة/خطوات، أو تخطيط مقسوم، أو تبويبات، أو تجميع دلاء.
- بطاقة الصنف بتبويباتها الأربعة (عام/وحدات/بضاعة أول المدة/المكونات) مطابقة لـ `frmItems.xaml`.
- بطاقات المؤشرات تعرض الكمية **والقيمة** معاً حيثما وُجدت قيمة.
- مطابقة تسميات الأعمدة لمراجع `Desktop_ERP` في القسم (2) بنسبة لا تقل عن 90٪.
